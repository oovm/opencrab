# 调度（Scheduler）

**调度系统**管理定时任务和日程，让智能体能够在指定时间执行任务。

## 核心概念

### 调度任务
需要定时执行的任务，包括一次性任务、周期任务、间隔任务等。

### 调度类型
- **一次性**：在指定时间执行一次
- **Cron**：按 Cron 表达式周期执行
- **间隔**：按固定时间间隔执行

## 设计理念

调度系统的设计遵循"可靠调度"原则：

1. **持久化**：调度任务持久化存储，系统重启后自动恢复
2. **事件通知**：任务执行通过事件触发，与智能体系统解耦
3. **状态管理**：任务状态清晰可追踪：待执行、执行中、已完成、失败、已取消
4. **错误处理**：任务执行失败有重试机制

## 调度任务

### 任务属性

一个调度任务通常包含以下属性：

- **ID**：任务的唯一标识
- **名称**：任务的名称
- **描述**：任务的描述
- **类型**：任务的调度类型（一次性、Cron、间隔）
- **执行时间**：任务的执行时间或调度表达式
- **任务内容**：任务要执行的具体内容
- **参数**：任务执行的参数
- **状态**：任务的当前状态
- **创建时间**：任务的创建时间
- **最后执行时间**：任务最后一次执行的时间
- **下次执行时间**：任务下次执行的时间
- **重试次数**：任务失败后的重试次数
- **最大重试次数**：任务的最大重试次数

### 任务类型

#### 一次性任务
在指定的时间点执行一次。

**适用场景：**
- 定时提醒
- 一次性任务执行
- 特定时间的操作

#### Cron 任务
按照 Cron 表达式周期性执行。

**Cron 表达式格式：**
```
秒 分 时 日 月 周
```

**示例：**
- `0 0 9 * * *`：每天上午 9 点执行
- `0 0 12 * * 1-5`：工作日中午 12 点执行
- `0 0 0 1 * *`：每月 1 号零点执行

**适用场景：**
- 定期报告生成
- 定时数据备份
- 周期性任务执行

#### 间隔任务
按照固定的时间间隔执行。

**示例：**
- 每 5 分钟执行一次
- 每小时执行一次
- 每天执行一次

**适用场景：**
- 定期检查
- 数据同步
- 健康检查

## 任务状态

调度任务具有以下状态：

| 状态 | 描述 |
|------|------|
| **待执行** | 任务等待执行 |
| **执行中** | 任务正在执行 |
| **已完成** | 任务执行成功 |
| **失败** | 任务执行失败 |
| **已取消** | 任务已被取消 |

## 任务生命周期

### 创建任务
1. 定义任务的基本信息
2. 设置调度类型和执行时间
3. 配置任务内容和参数
4. 保存任务到持久化存储

### 调度任务
1. 调度器扫描待执行任务
2. 判断任务是否到达执行时间
3. 将任务加入执行队列
4. 更新任务状态为执行中

### 执行任务
1. 从执行队列取出任务
2. 执行任务内容
3. 记录执行结果
4. 更新任务状态

### 完成任务
1. 任务执行成功，状态更新为已完成
2. 对于周期任务，计算下次执行时间
3. 保存任务状态

### 失败处理
1. 任务执行失败，状态更新为失败
2. 检查是否需要重试
3. 如果需要重试，计算重试时间
4. 更新任务状态为待执行

### 取消任务
1. 用户或系统取消任务
2. 更新任务状态为已取消
3. 清理相关资源

## 错误处理

### 重试机制
- 任务执行失败后自动重试
- 可配置最大重试次数
- 可配置重试间隔
- 指数退避策略

### 错误通知
- 任务失败时发送通知
- 支持多种通知方式
- 可配置通知接收者

### 失败记录
- 记录失败原因
- 记录失败时间
- 记录失败堆栈
- 便于问题排查

## 持久化

### 存储机制
- 任务信息持久化存储
- 支持多种存储后端
- 系统重启后自动恢复

### 存储内容
- 任务基本信息
- 任务调度配置
- 任务执行历史
- 任务状态信息

## 事件通知

### 任务事件
- 任务创建事件
- 任务执行事件
- 任务完成事件
- 任务失败事件
- 任务取消事件

### 事件订阅
- 支持事件订阅
- 支持事件处理
- 与智能体系统解耦
