# 能力（Capabilities）

**能力（Capability）**是智能体的外在扩展，是智能体"能调用什么"，通过工具或 API 实现。能力决定了智能体的操作边界。

## 能力与技能的区别

| 概念 | 说明 | 来源 |
|------|------|------|
| **技能（Skill）** | 内在能力，是智能体"懂什么"、"会做什么" | 通过学习或配置获得 |
| **能力（Capability）** | 外在扩展，是智能体"能调用什么" | 通过工具或 API 实现 |

这种区分的设计意图是：技能决定智能体的专业领域，能力决定智能体的操作边界。

## 能力的特点

能力具有以下特点：

- **外部依赖**：能力依赖于外部工具或 API
- **权限控制**：能力通常需要明确的权限授权
- **可配置**：能力可以根据需要启用或禁用
- **可审计**：能力的使用可以被记录和审计

## 能力的类型

能力可以分为以下几类：

### 文件系统能力
- 读取文件
- 写入文件
- 列出目录
- 创建目录
- 删除文件/目录

### 网络通信能力
- 发送 HTTP 请求
- WebSocket 连接
- 网络下载
- API 调用

### 系统操作能力
- 执行 Shell 命令
- 启动进程
- 管理系统资源
- 访问环境变量

### 数据存储能力
- 数据库操作
- 缓存读写
- 对象存储访问
- 向量数据库查询

### AI 模型能力
- 调用 LLM 模型
- 图像生成
- 语音识别
- 文本转语音

## 能力的授权模型

能力采用明确的授权模型：

1. **声明式配置**：在配置文件中声明可用的能力
2. **权限粒度**：支持细粒度的权限控制
3. **运行时检查**：每次能力调用前进行权限检查
4. **审计记录**：所有能力调用都有日志记录

## 能力的安全原则

能力系统的设计遵循"安全可控"原则：

1. **最小权限原则**：只授予必要的能力
2. **明确授权**：能力必须经过明确授权才能使用
3. **参数校验**：能力调用前进行参数校验
4. **结果封装**：能力执行结果统一封装
5. **可审计**：所有能力调用都有日志记录

## 能力与工具的关系

能力与工具密切相关但又有所不同：

- **工具（Tool）**：是具体的功能实现，提供能力的载体
- **能力（Capability）**：是智能体能够使用工具的权限和范围

一个工具可能提供多种能力，而一种能力也可能通过多个工具来实现。
