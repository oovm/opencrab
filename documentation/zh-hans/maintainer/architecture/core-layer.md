# 核心层设计

核心层是 OpenCrab 的核心业务逻辑层，包含智能体节点的核心功能。

## 概述

核心层采用模块化、高内聚低耦合的结构设计。每个核心模块专注于单一职责，通过清晰的接口交互。

### 设计定位

核心层在整个架构中承担"大脑"的角色：

- **向上**：为客户端库层提供稳定的业务接口
- **向下**：依赖基础设施层的通用能力
- **横向**：模块间通过 trait 接口协作，保持松耦合

### 核心设计理念

核心层的设计围绕"智能体"这一核心概念展开。智能体是具有自主决策能力的 AI 实体，能够感知环境、思考决策、执行动作、学习进化。整个核心层的设计都服务于让智能体更好地完成这些核心能力。

## 各模块设计理念

### 1. crab-agent - 智能体管理

智能体管理模块是核心层的"心脏"，负责智能体的生命周期管理、任务执行和协作。

#### 核心概念

**智能体（Agent）**：具有自主决策能力的 AI 实体，是系统的核心执行单元。智能体不是简单的请求-响应处理器，而是一个能够持续运行、主动思考、自主行动的实体。

**会话（Session）**：智能体与用户的一次交互会话。会话承载了消息历史和上下文，是智能体理解用户意图的基础。

**任务（Task）**：分配给智能体的工作单元。任务可以是对话回复、代码生成、文件操作等，智能体根据任务类型选择合适的执行策略。

#### 设计理念

智能体的核心设计遵循"感知-思考-行动-学习"循环：

1. **感知（Perceive）**：智能体从环境中获取信息，包括用户消息、系统事件、外部数据等。感知层的设计要支持多种信息源，并能够过滤和优先级排序。

2. **思考（Think）**：智能体基于感知到的信息进行推理和决策。思考过程涉及记忆检索、上下文理解、目标分解、计划制定等。设计上要支持不同的思考策略（快速响应 vs 深思熟虑）。

3. **行动（Act）**：智能体执行决策产生的动作。动作可以是回复消息、调用工具、执行技能等。行动层要保证执行的安全性和可追溯性。

4. **学习（Learn）**：智能体从行动结果中学习，更新记忆和知识。学习层的设计要支持增量学习和遗忘机制。

#### 模块关系

智能体模块是核心层的协调中心：

- 依赖 `crab-skill` 获取可执行的技能
- 依赖 `crab-tool` 获取可调用的工具
- 依赖 `crab-memory` 存储和检索记忆
- 依赖 `crab-chat` 处理消息交互
- 依赖 `crab-scheduler` 管理定时任务

---

### 2. crab-skill - 技能系统

技能系统模块管理智能体的内在工作能力。

#### 核心概念

**技能（Skill）**：智能体的内在工作能力，如代码审查、文档写作、数据分析等。技能是智能体"会做什么"的体现。

**技能与能力的区别**：

- **技能（Skill）**：内在能力，是智能体"懂什么"、"会做什么"，通过学习或配置获得
- **能力（Capability）**：外在扩展，是智能体"能调用什么"，通过工具或 API 实现

这种区分的设计意图是：技能决定智能体的专业领域，能力决定智能体的操作边界。

#### 设计理念

技能系统的设计遵循"插件化"原则：

1. **可注册**：技能可以动态注册和卸载，支持运行时扩展
2. **可组合**：多个技能可以组合使用，形成更复杂的能力
3. **可配置**：每个智能体可以配置不同的技能组合，实现角色差异化
4. **可版本化**：技能支持版本管理，便于升级和回滚

#### 技能生命周期

技能从注册到执行经历以下阶段：

1. **注册**：技能被注册到技能管理器
2. **发现**：智能体根据任务需求发现相关技能
3. **准备**：技能准备执行环境和上下文
4. **执行**：技能执行核心逻辑
5. **输出**：技能返回执行结果

---

### 3. crab-memory - 记忆系统

记忆系统模块管理智能体的短期和长期记忆。

#### 核心概念

**短期记忆**：当前会话的上下文，包括对话历史、临时状态等。短期记忆的生命周期与会话绑定，会话结束后自动清理。

**长期记忆**：历史经验和知识，包括用户偏好、学习到的知识、重要事件等。长期记忆需要持久化存储，支持跨会话检索。

**记忆重要性**：每条记忆都有重要性分数，用于决定记忆的保留优先级和检索排序。重要性分数可以基于访问频率、时间衰减、用户反馈等因素动态调整。

#### 设计理念

记忆系统的设计灵感来自人类记忆机制：

1. **分层存储**：短期记忆和长期记忆分离，各有不同的存储策略和访问模式
2. **语义检索**：支持基于语义相似度的记忆检索，而非简单的关键词匹配
3. **遗忘机制**：不重要的记忆会被自动遗忘，避免记忆膨胀
4. **关联强化**：频繁访问的记忆会被强化，提高检索优先级

#### 记忆类型

系统支持多种记忆类型，各有不同的用途：

- **消息记忆**：对话消息的记录
- **任务记忆**：任务执行的过程和结果
- **经验记忆**：从交互中学习的经验
- **知识记忆**：外部知识库的导入

---

### 4. crab-chat - 聊天系统

聊天系统模块处理消息和对话。

#### 核心概念

**消息（Message）**：聊天系统的基本单元，包含发送者、内容、状态等信息。消息支持多种内容类型：文本、图片、文件、混合内容等。

**消息状态**：消息从创建到送达经历多个状态：发送中、已发送、已送达、已读、失败。状态管理确保消息传输的可靠性。

**发送者类型**：消息可以来自用户、智能体或系统，不同类型的发送者有不同的处理逻辑。

#### 设计理念

聊天系统的设计遵循"可靠传输"原则：

1. **状态追踪**：每条消息都有明确的状态，便于追踪传输过程
2. **事件驱动**：消息状态变化通过事件通知，支持实时更新
3. **历史管理**：支持消息历史的分页查询和删除
4. **多端同步**：支持多客户端的消息同步

---

### 5. crab-tool - 工具系统

工具系统模块管理智能体的外部工具调用。

#### 核心概念

**工具（Tool）**：智能体的外部扩展功能，如调用 API、访问文件系统、执行命令等。工具是智能体"能调用什么"的体现。

**工具与技能的关系**：

- 技能是智能体的内在能力，决定智能体的专业领域
- 工具是智能体的外在扩展，决定智能体的操作边界
- 技能可以调用工具来完成复杂任务

#### 设计理念

工具系统的设计遵循"安全可控"原则：

1. **权限控制**：每个工具都有明确的权限要求，智能体只能在授权范围内调用
2. **参数校验**：工具调用前进行参数校验，确保调用安全
3. **结果封装**：工具执行结果统一封装，包含成功/失败状态和错误信息
4. **可审计**：所有工具调用都有日志记录，便于审计和调试

#### 内置工具

系统提供一组内置工具，覆盖常见场景：

- **文件工具**：读写文件、列出目录
- **Shell 工具**：执行命令
- **记忆工具**：保存和检索记忆
- **时间工具**：获取当前时间
- **HTTP 工具**：发送 HTTP 请求
- **MCP 工具**：支持 MCP 协议

---

### 6. crab-scheduler - 调度系统

调度系统模块管理定时任务和日程。

#### 核心概念

**调度任务（Scheduled Job）**：需要定时执行的任务，包括一次性任务、周期任务、间隔任务等。

**调度类型**：

- **一次性**：在指定时间执行一次
- **Cron**：按 Cron 表达式周期执行
- **间隔**：按固定时间间隔执行

#### 设计理念

调度系统的设计遵循"可靠调度"原则：

1. **持久化**：调度任务持久化存储，系统重启后自动恢复
2. **事件通知**：任务执行通过事件触发，与智能体系统解耦
3. **状态管理**：任务状态清晰可追踪：待执行、执行中、已完成、失败、已取消
4. **错误处理**：任务执行失败有重试机制

---

### 7. crab-workspace - 工作区管理

工作区管理模块管理文件和项目。

#### 核心概念

**工作区（Workspace）**：一个独立的工作环境，包含一组相关的文件和目录。工作区是智能体操作文件的基本单位。

**文件信息（FileInfo）**：文件的元数据，包括路径、类型、大小、修改时间等。

#### 设计理念

工作区管理的设计遵循"隔离安全"原则：

1. **边界隔离**：每个工作区有明确的边界，智能体只能在授权的工作区内操作
2. **路径安全**：所有文件操作都经过路径校验，防止路径穿越攻击
3. **抽象存储**：支持多种存储后端，便于扩展和迁移
4. **搜索支持**：支持文件名和内容的搜索

## 模块依赖关系

```
crab-types (基础设施层)
    ↑
    ├─ crab-agent
    │   ├─ crab-skill
    │   ├─ crab-memory
    │   ├─ crab-tool
    │   └─ crab-chat
    ├─ crab-skill
    ├─ crab-memory
    ├─ crab-chat
    ├─ crab-tool
    ├─ crab-scheduler
    └─ crab-workspace
```

### 依赖设计意图

**crab-types 作为基础**：所有模块都依赖 `crab-types`，确保类型定义的一致性。`crab-types` 定义了核心的 ID 类型、错误类型、通用 trait 等，是模块间协作的"通用语言"。

**crab-agent 作为协调中心**：`crab-agent` 依赖其他核心模块，但不被任何核心模块依赖。这种单向依赖确保了智能体模块的协调者角色，避免了循环依赖。

**功能模块的独立性**：`crab-skill`、`crab-memory`、`crab-tool`、`crab-chat` 等模块相互独立，可以单独测试和复用。它们之间的协作通过 `crab-agent` 协调，或通过事件系统异步通信。

## 设计原则总结

核心层的设计遵循以下原则：

### 高内聚

每个模块专注于单一职责。例如：

- `crab-memory` 只负责记忆的存储和检索，不关心记忆如何被使用
- `crab-tool` 只负责工具的注册和执行，不关心工具被谁调用

高内聚带来的好处：模块边界清晰，职责明确，易于理解和维护。

### 低耦合

模块间通过清晰的 trait 接口交互，而非直接依赖具体实现。例如：

- `crab-agent` 依赖 `MemorySystem` trait，而非具体的内存实现
- `crab-tool` 依赖 `Tool` trait，工具的具体实现可以自由替换

低耦合带来的好处：模块可以独立开发、测试和替换，系统更灵活。

### 可测试

每个模块都可以独立测试，不依赖其他模块的具体实现。通过 mock trait 实现，可以隔离测试单个模块的逻辑。

可测试带来的好处：提高代码质量，降低回归风险。

### 可扩展

支持插件和扩展机制。新的技能、工具、存储后端都可以通过实现 trait 来扩展，无需修改核心代码。

可扩展带来的好处：系统可以持续演进，适应新的需求。
