# OpenCrab 架构总设计

## 概述

**OpenCrab** 是一个单机智能体节点系统，参考了 `wae`、`game-gpt` 等优秀架构的设计理念，采用模块化、分层、高内聚低耦合的架构原则。

### 核心设计理念

1. **模块化设计**：每个功能模块独立成 crate，可单独测试和复用
2. **分层架构**：清晰的层次划分，职责明确
3. **Capability 模式**：能力驱动的设计，通过 trait 定义能力
4. **依赖注入**：使用代数效应风格的依赖管理
5. **协议优先**：协议层独立，支持多种应用形态

### 各层职责说明

#### 1. 应用层 (Applications)

应用层是用户直接交互的界面，包含多个同级应用，统一采用 `oh-my-*` 命名规范。

**主要应用：**
- `oh-my-crab` - 智能体客户端应用
- `oh-my-empire` - 帝国管理应用
- `oh-my-waifu` - 虚拟伴侣应用
- `oh-my-planet` - 星球探索应用
- `oh-my-home` - 智能家居应用
- `oh-my-claw` - CLI 命令行工具

**特点：**
- 所有应用为同级关系，共享核心层和基础设施层
- 支持多账号切换
- 统一的用户体验设计

#### 2. 核心层 (Core Layer)

核心层是系统的核心业务逻辑层，包含智能体节点的核心功能，统一采用 `crab-*` 命名规范。

**主要模块：**
- `crab-agent` - 智能体管理
- `crab-skill` - 技能系统
- `crab-memory` - 记忆系统
- `crab-chat` - 聊天系统
- `crab-tool` - 工具系统
- `crab-scheduler` - 调度系统
- `crab-workspace` - 工作区管理
- `crab-types` - 核心类型定义

**职责：**
- 实现智能体核心逻辑
- 管理技能和工具
- 处理记忆和上下文
- 提供聊天和协作功能

#### 3. 基础设施层 (Infrastructure)

基础设施层提供通用的基础设施服务，统一采用 `crab-*` 命名规范，参考 wae 的模块化设计。

**主要模块：**
- `crab-config` - 配置管理
- `crab-database` - 数据库抽象
- `crab-cache` - 缓存抽象
- `crab-http` - HTTP/HTTPS 服务
- `crab-effect` - 代数效应依赖注入
- `crab-queue` - 队列系统
- `crab-event` - 事件系统
- `crab-storage` - 存储抽象

**职责：**
- 提供通用基础设施
- 抽象底层技术细节
- 支持可插拔的实现

#### 4. 协议层 (Protocols)

协议层提供标准化的通信协议，统一采用 `skynet-*` 命名规范，是系统的基础设施。

**主要协议：**
- `skynet-types` - 基础类型定义
- `skynet-auth` - 认证协议
- `skynet-chat` - 聊天协议
- `skynet-gateway` - 网关协议
- `skynet-memory` - 存储协议
- `skynet-service` - 服务协议
- 其他协议...

**职责：**
- 提供标准化的通信协议
- 支持去中心化网络互联
- 定义数据格式和接口规范

## 核心设计模式

### 1. Capability 模式

每个能力定义为独立的 trait，通过实现多个 Capability 来声明支持的能力。

```rust
pub trait ChatCapability {
    async fn chat(&self, message: &str) -> Result<String>;
}

pub trait MemoryCapability {
    async fn save(&self, key: &str, value: &[u8]) -> Result<()>;
    async fn load(&self, key: &str) -> Result<Option<Vec<u8>>>;
}

pub struct Agent {
    // ...
}

impl ChatCapability for Agent { /* ... */ }
impl MemoryCapability for Agent { /* ... */ }
```

### 2. 代数效应依赖注入

采用代数效应风格的依赖注入，通过单一的 `Effectful` 参数统一管理所有依赖。

```rust
async fn handler(e: Effectful) -> Result<Json<Response>, EffectError> {
    let db = e.use_database().await?;
    let config = e.use_config::<AppConfig>().await?;
    let user = e.use_auth::<User>().await?;
    let cache = e.use_arc::<Cache>().await?;
    // ...
}
```

### 3. 模块化 Crate 设计

每个功能模块独立成 crate，可单独测试和复用。

**特点：**
- 清晰的依赖关系
- 可单独编译和测试
- 易于替换和扩展
- 最小化耦合

### 4. 分层架构

清晰的层次划分，每层都有明确的职责和边界。

**层次间的调用规则：**
- 上层可以调用下层
- 下层不能调用上层
- 同层之间可以互相调用
- 避免跨层调用

## 关键模块设计原则

### 基础设施层设计原则

参考 wae 的设计：

1. **抽象优先**：先定义 trait，再提供实现
2. **多后端支持**：支持多种实现（如数据库支持 SQLite、PostgreSQL 等）
3. **零抽象开销**：在性能关键路径上保持零抽象
4. **统一错误处理**：统一的错误类型和处理方式

### 核心层设计原则

参考 ironclaw 的优秀特性，但重新组织：

1. **高内聚**：每个模块专注于单一职责
2. **低耦合**：模块间通过清晰的接口交互
3. **可测试**：易于单元测试和集成测试
4. **可扩展**：支持插件和扩展机制

### 应用层设计原则

1. **同级关系**：所有 oh-my-* 应用为同级关系
2. **共享核心**：共享核心层和基础设施层
3. **独立体验**：每个应用有独立的用户体验设计
4. **统一风格**：遵循统一的设计规范

## 与其他项目的关系

### 与 Skynet 协议的关系

- **Skynet 协议**：是互联协议，定义节点间的通信标准
- **OpenCrab**：是单机智能体节点，实现 Skynet 协议
- **关系**：OpenCrab 基于 Skynet 协议构建，支持与其他节点互联

### 与 ai-company 的关系

- **OpenCrab**：单机智能体节点
- **ai-company**：联合端
- **关系**：两者都基于 Skynet 协议，可互联互通

### oh-my-* 系列应用的关系

- 所有 oh-my-* 应用共享相同的架构
- 共享基础设施层和协议层
- 核心层根据不同应用场景定制
- 可互联互通，形成生态系统

## 总结

OpenCrab 架构设计遵循以下核心原则：

1. **模块化**：每个功能独立成 crate
2. **分层**：清晰的四层架构
3. **抽象**：通过 trait 定义能力
4. **可扩展**：支持插件和扩展
5. **可测试**：易于测试和验证

这个架构参考了 wae、game-gpt 等优秀项目的设计理念，但不是简单的抄袭，而是根据 OpenCrab 的具体需求进行了重新设计和优化。
