# 基础设施层设计

基础设施层提供通用的基础设施服务，采用模块化设计理念。

## 概述

**重要说明：OpenCrab 现已直接依赖 WAE 项目的基础设施模块，不再维护独立的 crab-* 基础设施模块。**

基础设施层是 OpenCrab 的底层支撑，提供通用的、可复用的基础设施服务。所有基础设施模块现在来自 **WAE 项目**，每个模块都遵循**抽象优先**的设计原则，先定义 trait，再提供多种实现。

## 模块列表

| 模块 | 功能 | 来源 |
|------|------|------|
| `wae-types` | 核心类型定义 | WAE |
| `wae-config` | 配置管理 | WAE |
| `wae-database` | 数据库抽象 | WAE |
| `wae-cache` | 缓存抽象 | WAE |
| `wae-https` | HTTP/HTTPS 服务 | WAE |
| `wae-effect` | 代数效应依赖注入 | WAE |
| `wae-queue` | 队列系统 | WAE |
| `wae-event` | 事件系统 | WAE |
| `wae-storage` | 存储抽象 | WAE |

---

## 与 OpenCrab 的关系

### 依赖关系

OpenCrab 核心层（crab-*）直接依赖 WAE 基础设施模块：

```
crab-agent, crab-skill, crab-memory, ...
    ↓
wae-config, wae-database, wae-cache, ...
```

### 为什么选择 WAE

1. **成熟稳定**：WAE 是经过验证的基础设施框架
2. **持续维护**：WAE 项目有活跃的维护和更新
3. **功能完善**：提供完整的基础设施组件
4. **设计优秀**：遵循抽象优先、多后端支持等优秀设计原则
5. **避免重复**：不再需要维护重复的基础设施代码

## 各模块概述

### 1. wae-types - 核心类型定义

核心类型定义模块，提供统一的错误类型、结果类型和通用数据结构。

### 2. wae-config - 配置管理

配置管理模块，支持多层级配置（TOML/YAML/环境变量）。

### 3. wae-database - 数据库抽象

数据库抽象模块，支持多种数据库后端（SQLite、PostgreSQL、MySQL 等）。

### 4. wae-cache - 缓存抽象

缓存抽象模块，支持多种缓存后端（内存缓存、Redis 等）。

### 5. wae-https - HTTP/HTTPS 服务

HTTP/HTTPS 服务模块，提供 Web 服务能力。

### 6. wae-effect - 代数效应依赖注入

代数效应风格的依赖注入模块。

### 7. wae-queue - 队列系统

队列系统模块，支持异步任务处理。

### 8. wae-event - 事件系统

事件系统模块，支持事件发布和订阅。

### 9. wae-storage - 存储抽象

存储抽象模块，支持多种存储后端（本地文件系统、COS、OSS、S3 等）。

## 设计原则总结

WAE 基础设施层的设计遵循以下原则：

1. **抽象优先**：先定义 trait，再提供实现
2. **多后端支持**：支持多种实现，易于切换
3. **零抽象开销**：在性能关键路径上保持零抽象
4. **统一错误处理**：统一的错误类型和处理方式
5. **易于测试**：易于单元测试和集成测试
6. **完整文档**：所有公共 API 都有文档注释

这些原则确保基础设施层的高质量和可维护性，为上层业务逻辑提供稳定可靠的基础支撑。
