# 重构核心层架构文档 Spec

## Why

当前 `core-layer.md` 包含大量具体的 Rust 代码示例（如完整的结构体定义、方法签名等），这与架构文档的定位不符。架构文档应该阐述**核心设计理念和思路理解**，具体代码实现应该让读者直接查看源代码。

## What Changes

- 移除所有具体的 Rust 代码示例
- 重写为概念性的设计理念阐述
- 增加各模块的核心概念说明
- 强调模块间的关系和协作方式
- 补充设计原则和思路的深度解释

## Impact

- Affected files: `documentation/zh-hans/maintainer/architecture/core-layer.md`

## ADDED Requirements

### Requirement: 架构文档应聚焦设计理念

架构文档应该解释"为什么这样设计"、"各部分之间的关系"、"核心概念"，而不是展示具体代码实现。

#### Scenario: 读者阅读核心层文档

- **WHEN** 维护者阅读核心层架构文档
- **THEN** 应该理解各模块的设计理念、职责边界、模块间关系
- **AND** 不需要看到具体的 Rust 代码实现

### Requirement: 各模块应阐述核心概念

每个核心模块应该清晰阐述其核心概念、职责、与其他模块的关系，而非罗列 API。

#### Scenario: 理解智能体模块

- **WHEN** 读者阅读 crab-agent 模块说明
- **THEN** 应该理解智能体的核心概念（自主决策能力、执行单元）
- **AND** 理解智能体与会话、任务的关系
- **AND** 理解智能体循环的设计理念（感知-思考-行动-学习）

### Requirement: 设计原则应有深度解释

设计原则部分应该深入解释每个原则的含义、应用方式、带来的好处。

#### Scenario: 理解高内聚低耦合

- **WHEN** 读者阅读设计原则
- **THEN** 应该理解高内聚低耦合在本项目中的具体体现
- **AND** 理解如何通过接口隔离实现低耦合
